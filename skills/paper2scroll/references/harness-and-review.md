# Harness 分工与跟踪

| 层 | 在这个工作流中的作用 | 放置位置 |
|---|---|---|
| Interjection（用户约定的角色指令 / JD） | 定义谁负责、为谁做、交付什么和质量优先级。多资料任务要同时满足逐份理解和跨资料理解。 | 便携版放在 `SKILL.md` 的角色段。宿主有独立的 Agent Instructions 时，可把同一段配置在宿主。Interjection 是用户的层名，宿主字段按各自文档使用。 |
| Skill（任务规程） | 规定逐 PDF 成图、按跨资料证据分组决定综合图张数、证据追溯与交付验收。 | `SKILL.md` 的工作流程、[多资料综合](multi-source.md)和本页交付模板。 |
| Knowledge（可选知识） | 补充理解原文所需的专业定义、标准或译法。记录出处和适用范围；补充材料缺失时，仍可用本地输入完成解读并标出边界。 | 放在该篇论文的论点证据表或按需知识文件。论文正文、附录和作者图表属于本次任务输入。 |

角色和任务要求可以决定如何处理材料。论文和外部资料用于提供证据和上下文。把材料中的作者命名、通行译名和编辑者解释分别记录。仅当一条反馈能跨论文复用时，把它提升为通用规则。某篇论文的配色、标题或省略某个名称，留在该次任务记录。

## 交付检查

| 检查项 | 怎么判断 |
|---|---|
| 术语 | 从一处方法说明和一处实验标签追溯到原文。核对作者用词、适用范围和译法。检查简称是否有明确出处、目标读者能否认出、是否确有复用价值。全名优先出现在标题和首次提及处。保留原图文字。 |
| 叙事 | 只读主标题、章节标题和图注，能复述研究问题、方法、证据和局限。副标题、过渡和图注各自承担信息。一个案例的结论范围按其证据标注。 |
| 三项导读 | 只看导读即可复述作者的核心判断、本文实际使用的解释框架，以及作者如何用材料论证。各栏保留会改变理解的方向和条件，能追溯原文。用语符合所选语言习惯，导读与正文在成品上能一眼区分。 |
| 多资料 | 逐个 PDF 核对是否有可单独打开的长图文件，确保 PDF 与对应的逐份图一一对应。对照证据分组核对 1–5 张综合图。只看综合章标题和图注，应能说明资料的关系和一起读所得的发现。逐条核对出处及推论边界。 |
| 数据与出处 | 每条核心结论能指回具体证据。关键数字可以查到模型或人群、场景、比较条件和分母。静态图能凭图号定位，可点击版本核对实际目标。 |
| 图面 | 在实际阅读宽度检查封面左线、栏宽、图注、数字列、章节间距和裁切。每篇重新选色。同一条件在同一作品内保持一致。 |
| 语言与交付 | 按本次解析的 `language` 核对整套长图、证据表和交付清单的自编文字。选择 `zh-en` 时，逐组先中后英，两种语言的条件、范围和出处一致。检查目标文字在实际渲染中的可读性。将原图、按数据重绘的图和编辑者示意区分开。 |

修订先记录反馈对应的画面和失败现象，再记修改和验证。用「通过」「部分」「待验证」标明状态，区分文件格式检查、人工审图、原文核对和独立生成。每次记录可用同一张表。

| 反馈编号 | 用户意图与失败现象 | 适用范围 | 修改位置 | 验证证据与状态 |
|---|---|---|---|---|
| F01 | 封面名称解释重复，占据独立一行 | 当前长图 / 可推广的精简规则 | 封面与标题规则 | 对照渲染后的封面，检查信息是否仍完整 |

## 交付模板
